# 데이터 분류·라우팅 규칙 템플릿

## 3등급 분류 가이드

### 🟢 1급 — 공개 OK

특징: 외부에 공개되거나 *공개돼도 문제 없음*.
예시:
- 블로그 글 초안
- 공개 문서·README
- 회의 안건 (외부와 공유하는)

라우팅: **어떤 클라우드 LLM이든 OK**

### 🟡 2급 — 주의

특징: *내부용*이지만 *심각한 위험*은 아닌 것. 익명화하면 외부 사용 가능.
예시:
- 회사 내부 회의록 (사람 이름 익명화 필요)
- 개인 일정·할 일
- 내부 코드 (비밀 키 없는 부분)

라우팅: **익명화 후 클라우드** OR **로컬 LLM**

### 🔴 3급 — 절대 클라우드 X

특징: 노출 시 *심각한 영향*. 법적·재정적·신뢰 손실.
예시:
- 비밀번호·API 키·인증 정보
- 의료·법률·금융 정보
- 미공개 사업 계획·계약서

라우팅: **로컬 LLM에서만** 또는 **에이전트 호출에서 완전 제외**

## 라우팅 규칙 한 줄 (예시)

```
1급 → Claude/Gemini 등 클라우드 OK
2급 → 익명화 후 클라우드 또는 로컬 LLM
3급 → 로컬(Ollama)에서만 또는 절대 호출 X
```

## AGENTS.md에 추가할 표준 항목

```markdown
## 주의사항 (프라이버시)

- `.private/` 폴더 안 파일은 절대 외부 호출에 포함하지 않기
- 비밀 키·인증 정보는 환경 변수로만 관리
- 3급 데이터를 다룰 때는 *로컬 LLM*만 사용
- 의심되면 *상위 등급으로* 분류 (보수적)
```

## 자가 테스트 (5분)

본인 작업의 실제 데이터 5개를 떠올려 등급 매기기:

1. ___ → 등급: ___
2. ___ → 등급: ___
3. ___ → 등급: ___
4. ___ → 등급: ___
5. ___ → 등급: ___

매번 같은 등급이 나오는지 점검. 답이 흔들리면 *기준이 모호*하다는 뜻 → 규칙을 더 구체적으로.

## 안전 강화 (선택)

- 폴더 단위 격리: `.private/` 폴더는 git에 안 올라가게 `.gitignore`에 추가
- 자동 검사: pre-commit hook(9강)으로 *비밀 키 노출* 자동 탐지
- 정기 점검: 월 1회 *분류가 잘 지켜지는지* 자가 감사
