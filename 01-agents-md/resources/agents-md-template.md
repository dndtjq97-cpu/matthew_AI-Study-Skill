# AGENTS.md 표준 템플릿

> 이 파일은 *AGENTS.md의 표준 형식*을 정의합니다. 가이드 실습에서 에이전트가 초안을 만들 때 이 구조를 따릅니다. 학습자도 직접 참고할 수 있어요.

---

## 1. 6개 표준 섹션

| # | 섹션 | 무엇을 적나 | 필수/선택 |
|---|---|---|---|
| 1 | 프로젝트 개요 | 무엇을 하는 곳, 누구를 위한 것, 어떤 결과물 | **필수** |
| 2 | 톤과 스타일 | 톤(말투), 결과물 형식, 행동 규칙 | **필수** |
| 3 | 자주 쓰는 명령 | 빌드·실행·테스트 등 자주 입력하는 명령 | **필수** |
| 4 | 주의사항 | 절대 하지 말 것 | **필수** |
| 5 | 도구·환경 | 언어, 라이브러리, 주요 서비스 | 선택 |
| 6 | 예시 | 잘된 결과 / 안 된 결과 | 선택 |

> 통과 기준: **필수 4개 중 3개 이상**이 채워지면 통과. 도구·환경과 예시는 비어 있어도 OK.

---

## 2. 빈 템플릿 (학습자가 직접 채울 형식)

```markdown
# AGENTS.md

## 프로젝트 개요
[이 프로젝트가 무엇을 하는 곳인지 한 단락으로 — 누구를 위한 것이고, 어떤 결과물을 만드는지]

## 톤과 스타일
- 톤: [친근한 존댓말 / 정중한 존댓말 / 캐주얼 등]
- 결과물 형식: [글 길이, 코드 한 줄 길이, 마크다운 사용 여부 등]
- 행동 규칙:
  - [규칙 1 — 예: "추측보다 모호하면 물어보기"]
  - [규칙 2]
  - [규칙 3]

## 자주 쓰는 명령
- 빌드: `<명령>`
- 실행: `<명령>`
- 테스트: `<명령>`
(없는 프로젝트면 "없음"이라고 적어도 OK)

## 주의사항
- [절대 하지 말 것 1 — 예: "main 브랜치에 직접 push 금지"]
- [절대 하지 말 것 2 — 예: "비밀번호·API 키를 코드에 직접 넣지 않기"]

## 도구·환경 (선택)
- 언어: [예: Python 3.11]
- 프레임워크/라이브러리: [예: FastAPI, pandas]
- 배포 환경: [예: Vercel, AWS Lambda]

## 예시 (선택)
- ✅ 좋은 답: [예: "한 줄 요약 후 단계별 설명"]
- ❌ 피할 답: [예: "출처 없이 단정"]
```

## 4. 작성 팁

### 짧고 분명하게
*한 페이지의 모호한 글*보다 *3줄의 명확한 글*이 훨씬 효과적입니다. 길이로 채우려고 애쓰지 마세요.

### 규칙은 2~3개부터
규칙이 너무 많으면 에이전트가 오히려 무시합니다. 정말 자주 부탁하게 되는 2~3개로 시작하고, 필요하면 천천히 늘리세요.

### 명령어는 *복붙 가능한 형태*로
`npm run build` 같이 그대로 실행 가능한 형태로 적어두세요. "빌드 명령" 같이 모호한 표기는 피하세요.

### 주의사항은 *행동 지침*으로
"조심하기"보다는 "X를 하지 말 것" 같은 명확한 동작으로 적으세요.

### 살아 있는 문서로
AGENTS.md는 한 번에 완벽할 필요가 없어요. 사용해보다가 *어색한 부분*을 그때그때 다듬으세요. 1주일 후, 1개월 후 다시 보면 자연스럽게 좋아져 있을 거예요.

## 5. 자주 묻는 질문

**Q. AGENTS.md를 여러 개 만들어도 되나요?**
A. 네. 큰 프로젝트에서는 폴더별로 다른 AGENTS.md를 둘 수 있어요. 에이전트는 *현재 작업 중인 폴더*의 AGENTS.md를 우선합니다.

**Q. README.md가 이미 있는데 AGENTS.md가 필요한가요?**
A. 네. README.md는 *사람*이 읽는 문서고, AGENTS.md는 *에이전트*가 읽는 문서예요. 둘 다 있는 게 좋아요.

**Q. CLAUDE.md / .cursorrules도 같이 만들어야 하나요?**
A. 보통은 AGENTS.md 하나면 충분해요. 도구별로 *진짜 다른 규칙*이 필요할 때만 도구 전용 파일을 추가하세요. (자세한 패턴은 `99-claude-specific/` 부록 참조)

**Q. 다른 사람이 봐도 되나요?**
A. 네. 팀 프로젝트라면 git에 같이 올려두세요. 팀원과 에이전트가 같은 맥락에서 일하게 됩니다. 다만 *비밀 정보*(API 키 등)는 절대 적지 마세요.
