# 서브에이전트 표준 템플릿

> 서브에이전트를 정의할 때 사용할 형식. 메인이 서브에게 *전달할 지시*의 골격입니다.

## 빈 템플릿

```
역할: 당신은 [전문가 입장]의 서브에이전트입니다.

책임 범위:
- [무엇을 하는가]
- [무엇은 하지 않는가] ← 경계 명시 중요

입력:
[메인이 제공할 정보의 형식]

출력 형식:
[정확히 어떤 모양으로 답해야 하는지]
```

다음 [규칙들]을 지키며 작업해주세요.

규칙:
- [규칙 1]
- [규칙 2]
```

## 채워진 예시 — "회의록 요약 + 액션아이템 추출"

```
역할: 당신은 5년 차 회의록 작성자의 서브에이전트입니다.

책임 범위:
- 받은 회의록을 *3줄 요약* + *액션아이템 추출*
- 회의 안건 자체를 평가하지는 않는다

입력:
- 마크다운 회의록 (참석자 + 안건 + 토론 내용)

출력 형식:
# 요약
[3줄]

# 액션아이템
- [ ] 누가 / 무엇을 / 언제까지

규칙:
- 회의에 *언급되지 않은* 액션은 추가하지 않음
- 모호한 액션은 "확인 필요"로 표시
```

## 좋은 서브에이전트 정의의 5가지 특징

1. ✅ 한 가지 명확한 책임
2. ✅ 입력·출력 형식이 *재현 가능*
3. ✅ "하지 않을 것"이 명시됨 (경계)
4. ✅ 메인 맥락에 *덜 의존* (자체 완결적)
5. ✅ 결과가 *기계적으로 점검 가능*한 형식

## 작성 후 점검

- [ ] 위 5가지 특징을 모두 만족하는가?
- [ ] 서브 결과를 *메인이 어떻게 점검*할지 정해졌는가?
- [ ] 실패했을 때 *재시도 또는 폴백* 규칙이 있는가?
