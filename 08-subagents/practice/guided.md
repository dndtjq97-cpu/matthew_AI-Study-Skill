# Practice — 가이드 실습 (8강 서브에이전트)

> `_shared/guided-practice-protocol.md`의 7단계를 따릅니다.

## 0. 진입 직전 (draft 정리)

이론에서 적은 `parent_task` / `subagent_role` / `input_format` / `output_format`을 정리해 보여줌.

## 1. 옵션 제시 (2개 인라인)

```
어떤 작업으로 시연하시겠어요?

  (1) {{name}}님 본인 작업 (이론에서 적어주신 것)
  (2) 가상 사례 — 예: "긴 문서 → 요약 + 액션아이템 추출"

번호로 답해주세요.
```

## 2. 옵션 ① — 본인 작업

### 2-1. 사전 점검
- 도구의 *서브에이전트 지원* 확인 (부록 참조)
- 지원 안 되면 *순차 실행*으로 폴백

### 2-2. 비용 안내
- LLM 호출이 *2번 이상* 발생 (메인 + 서브)
- 토큰 비용 ↑ 가능. 자유 스킵 가능.

### 2-3. 서브에이전트 호출
학습자에게 트리거 표현 안내:

```
이제 메인 에이전트한테 시켜보세요.

  👉 "<draft.parent_task>를 시작해줘. 이 중 <draft.subagent_role> 부분은
       서브에이전트로 위임해서 결과를 받아 통합해줘."

진행 결과를 그대로 붙여넣어 주세요.
```

### 2-4. 결과 통합 점검
- 메인이 서브 결과를 *형식대로* 받았는지
- 메인의 다음 단계가 *깨지지 않고* 진행됐는지

## 3. 옵션 ② — 가상 사례

강의 제공 시나리오: "긴 회의록을 받아 액션아이템만 추출하는 서브에이전트". 메인이 회의록 받음 → 서브에 위임 → 결과 받아 정리.

## 4. 검증 기준

| 항목 | 통과 기준 |
|---|---|
| 서브 역할이 *명확히 한 가지 책임* | ✅ |
| 입출력 형식이 *재현 가능* | ✅ |
| 호출이 *실제로 동작* (1번 시연) | ✅ |

3개 중 *2개 이상* 통과 시 ✅.

## 5. 트러블슈팅

- 도구가 서브에이전트 미지원 → *순차 실행* 폴백 (한 대화에서 두 단계로 나누기)
- 서브 결과 형식 어긋남 → 형식 *명시* 강화 + 메인이 점검 한 줄 추가
