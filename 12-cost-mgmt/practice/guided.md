# Practice — 가이드 실습 (12강 비용 관리)

> `_shared/guided-practice-protocol.md`의 7단계 + **direct/indirect 학습자 자동 분기**.

## 0. 진입 직전 (draft 정리)

이론에서 적은 `api_user_type` / `current_monthly_estimate` / `top_3_calls` / `optimization_ideas`를 정리해 보여줌.

## 1. 옵션 제시 (학습자 유형에 따라 자동 분기)

```
{{name}}님은 [{{draft.api_user_type}}] 학습자이시니까 다음 중에서 골라주세요.

[direct 학습자]
  (1) 사용량 대시보드 직접 점검 + 절약 1가지 적용 (가장 추천)
  (2) 가상 사례로 연습

[indirect 학습자]
  (1) 본인 도구의 토큰 사용 패턴 점검 + 슬림화 1가지
  (2) 가상 사례로 토큰 절약 사고 연습
```

## 2. 옵션 ① — 본인 환경 적용

### direct 학습자 흐름
1. 가입한 제공자의 *사용량 대시보드* 접속
2. *최근 한 달 사용량* 한 번 확인 (`draft.current_monthly_estimate` 갱신)
3. *가장 비싼 호출* 식별 → `draft.top_3_calls`
4. 절약 패턴 1개 선택 (캐싱/슬림화/모델 다운그레이드 중)
5. 적용 → `draft.optimization_ideas`

### indirect 학습자 흐름
1. 본인 도구의 *컨텍스트 사용 패턴* 점검 (5강 내용 활용)
2. *어떤 부탁이 가장 무거운지* 1~3개 식별
3. 슬림화 1가지 적용 (예: 첨부 줄이기, 새 대화 분리)
4. 변화 체감 — 응답 속도, 답변 품질

## 3. 옵션 ② — 가상 사례

강의 제공 시나리오 — "한 달에 100달러 쓰는 사용자, 가장 비싼 작업이 *매일 10페이지 문서 첨부*". 함께 진단 → 슬림화 패턴 적용 → 예상 효과 계산.

## 4. 검증 기준

| 항목 | 통과 기준 |
|---|---|
| 토큰 개념을 *한 줄로 설명* 가능 | ✅ |
| *비싼 호출 1개* 식별 (또는 가상) | ✅ |
| 절약 패턴 *1개 적용* 또는 적용 계획 | ✅ |

3개 중 *2개 이상* 통과 시 ✅.

## 5. 트러블슈팅

- 대시보드 위치 못 찾음 → 가입한 제공자 도움말 페이지 안내
- 절약 후 *답변 품질이 떨어짐* → 줄인 자료 일부 복원 (5강 패턴)
