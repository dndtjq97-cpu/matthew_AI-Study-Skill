# Practice — 가이드 실습 (4강 프롬프트)

> `_shared/guided-practice-protocol.md`의 7단계를 따릅니다.

## 0. 진입 직전 (draft 정리)

이론에서 적은 `original_prompt` / `improved_prompt` / `applied_principles`를 정리해 학습자에게 보여줌. 수정 요청 시 해당 키만 덮어쓰기.

## 1. 옵션 제시 (2개 인라인)

```
어떻게 비교 호출을 해보시겠어요?

  (1) {{name}}님 본인 프롬프트로 비교 (이론에서 다듬어주신 것)
  (2) 강의가 제공하는 예시 프롬프트로 연습

번호로 답해주세요.
```

## 2. 옵션 ① — 본인 프롬프트 비교

### 2-1. 사전 점검
- 호출할 LLM 도구 또는 API 결정
- 두 버전(`original` / `improved`) 모두 호출할 *준비 OK*

### 2-2. 비용 안내
- LLM 호출 1회당 토큰 비용 발생 (대부분 무료 한도 안)
- 부담되시면 옵션 ②로 전환 가능

### 2-3. 호출 흐름

```
1. {{name}}님 환경에서 다음 두 프롬프트를 *각각* 호출해주세요.

   [원본]
   {{draft.original_prompt}}

   [다듬은 버전]
   {{draft.improved_prompt}}

2. 두 결과를 그대로 붙여넣어 주세요. 같이 비교해볼게요.
```

### 2-4. 비교·검증
- 결과 *길이·구조·관련성*을 함께 점검
- 학습자가 "어디가 좋아졌나" 한 줄로 정리
- `draft.comparison_result` 갱신

## 3. 옵션 ② — 예시 프롬프트 연습

강의가 제공하는 *모호 예시*와 *명확 버전* 한 쌍 (예: "회고 정리해줘" vs "5년 차 PM으로서 이번 주 회고를 잘된 점/아쉬운 점/액션으로 정리. 마크다운, 한 페이지").

학습자가 두 결과를 비교 분석.

## 4. 검증 기준

| 항목 | 통과 기준 |
|---|---|
| `improved_prompt`에 5요소 중 3개 이상 포함 | ✅ |
| 두 호출 결과가 *눈에 띄게 다름* (학습자가 차이 설명) | ✅ |
| 적용 원칙 1개 이상 명시 가능 | ✅ |

3개 중 *2개 이상* 통과 시 ✅. 부족한 부분 명확히 명시.

## 5. 트러블슈팅

- 두 결과가 너무 비슷함 → *제약·출력 형식*을 더 명시하라고 안내.
- 호출이 안 됨 → 도구별 호출 방법 부록 안내.

## 6. 마무리

- 통과: `practice_status = "done"`, `status = "completed"`
- 포기: `practice_status = "not_done"`
