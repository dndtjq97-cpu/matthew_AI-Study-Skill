# 디버깅 진단 체크리스트

> 에이전트가 막혔을 때 순서대로 던질 10개 질문.

## 체크리스트

1. **부탁이 명확한가?** (5요소: 역할/맥락/입력/제약/출력)
2. **필요한 입력이 다 들어왔나?** (자료 첨부 등)
3. **컨텍스트가 너무 길어 잘렸나?**
4. **사용하는 도구·MCP가 살아 있나?** (재시작 필요?)
5. **API 키·인증이 유효한가?** (만료, 한도 초과)
6. **네트워크가 연결되어 있나?**
7. **같은 부탁이 다른 환경에서는 되는가?** (다른 도구, 다른 시간)
8. **에러 메시지를 잘 읽었는가?** (마지막 줄부터)
9. **최근 무엇이 바뀌었나?** (도구 업데이트, 코드 수정 등)
10. **이 작업이 원래 어려운 종류인가?** (모델 한계)

## 5가지 흔한 실패 패턴

| 패턴 | 증상 | 점검 |
|---|---|---|
| 모호한 부탁 | 매번 다른 답 | 1번 |
| 컨텍스트 부족 | 자꾸 까먹음 | 2·3번 |
| 도구·권한 | 안 됨 | 4·5번 |
| 외부 상황 | 응답 없음 | 6번 |
| 모델 한계 | 정확도 낮음 | 10번 |

## 고립 (좁히기)

큰 작업이 안 될 때:
1. 작업을 *절반*으로 쪼갬
2. 앞 절반만 돌려봄 → 되면 뒤가 범인 / 안 되면 앞이 범인
3. 다시 절반으로 → 반복 (보통 3~4번이면 범인 단계 찾음)

## 도움 요청 5요소

남에게 도움 요청할 때 다음 5가지 포함:
1. 무엇을 하려고 했나 (목표)
2. 무엇이 안 됐나 (실제 결과)
3. 무엇이 *기대*됐나 (예상)
4. 어디까지 시도했나 (이미 점검한 것들)
5. 에러 메시지 그대로 (있다면)
