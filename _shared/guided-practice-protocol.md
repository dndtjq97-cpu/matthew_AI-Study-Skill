# Guided Practice Protocol — 가이드 실습 프로토콜

이 문서는 모든 강의의 *가이드 실습 모드*가 따르는 표준 흐름을 정의합니다.
이론 lesson(`teaching-protocol.md`)이 끝난 직후, 각 SKILL.md는 이 프로토콜을 호출합니다.

> 각 스킬의 SKILL.md 본문에 이 한 줄을 포함합니다:
> "이 스킬의 실습은 `_shared/guided-practice-protocol.md`의 흐름을 따릅니다."

---

## 0. 진입 (transition)

이론 lesson 마지막 청크가 끝나면, 다음 표준 안내문으로 가이드 실습 모드를 엽니다.

```
🎉 이론 끝! 이제 직접 해볼 차례예요.

여기서부터는 단순한 미션이 아니라, 매튜님이 옆에 앉아 함께 진행하는
실습 가이드예요. 막히면 언제든 알려주세요. 같이 풀어볼게요.

진행하시겠어요?
  (1) 네, 시작할게요
  (2) 일단 스킵할게요 (⚠ 실습 미이행으로 표시돼요)
```

학습자가 (2) 선택 → `practice_status: "not_done"` 갱신 후 강의 마무리.

---

## 1. 옵션 제시 (선택지 메뉴)

학습자가 *무엇을* 실습할지 고르게 합니다. 한 청크 안에 옵션을 보여주세요.

### 표준 형식
```
어떤 OOO을 해볼까요? 후보를 추천드릴게요.

  (1) 옵션 A — 한 줄 설명
  (2) 옵션 B — 한 줄 설명
  (3) 옵션 C — 한 줄 설명
  (4) 직접 입력 — 매튜님이 원하는 다른 것

번호 또는 이름을 입력해주세요.
```

### 옵션 폴더 사용 기준 (`practice/options/`)

| 옵션 개수 | 권장 구조 |
|---|---|
| 0~2개 | `practice/guided.md` 안에 인라인 분기 |
| **3개 이상** | **`practice/options/<option-id>.md` 분리** |

옵션 분리 시 좋은 점:
- 컨텍스트 절약 — 학습자가 선택한 옵션 파일만 에이전트가 로드
- 유지보수 용이 — 옵션별 독립 수정
- 확장 쉬움 — 새 옵션 = 새 파일

### "직접 입력" 처리
학습자가 (4) 또는 후보 외 항목을 입력하면:
- 에이전트가 그 항목이 *합리적으로 가능한지* 판단
- 가능 → 표준 7단계로 진행 (사전 점검 + 명령어 안내 즉석 생성)
- 의심 → "이건 제가 잘 모르는 영역이라 ~ 옵션을 추천드릴게요" 안내

---

## 2. 사전 점검 (pre-flight check)

선택된 옵션에 필요한 *준비물*을 확인합니다.

### 표준 점검 항목 (옵션마다 다름)
- 의존성: Node, Python, Docker 등 (`OS 맞춤 확인 명령` 제공)
- 계정·키: API 키, GitHub 계정 등
- 권한: 파일 시스템 접근 권한
- 💰 **비용** (다음 섹션 참조)

### 점검 명령은 학습자 OS 맞춤
`style-guide.md`의 OS 분기 자리표시자(`{{os:darwin}}`)를 사용합니다.

### 학습자 응답 받기
점검 결과를 학습자가 붙여넣으면 에이전트가 분석:
- 통과 → 다음 단계로
- 누락 → 누락된 것 설치 명령 안내 → 재점검

---

## 3. 💰 비용 투명성 — 의무 안내

API 키 발급, LLM 호출, 외부 유료 서비스 등 **비용 발생 가능성**이 있는 실습은
사전 점검 단계에서 다음을 *반드시* 안내합니다.

### 표준 비용 안내문

```
💰 **비용 안내**

이 실습은 외부 API를 사용해요. 다음을 미리 알아두세요:

  - **대부분 유료**예요. (무료 크레딧이 있는 경우만 처음에 무료)
  - 학습자 본인의 신용카드/결제 정보가 필요할 수 있어요.
  - 강의 진행에 비용이 걱정되면 **이 실습은 자유롭게 스킵하셔도 돼요.**
  - 스킵 시 ⚠ 실습 미이행으로 표시되지만, 다음 강의는 그대로 진행돼요.

어떻게 하시겠어요?
  (1) 네, 시작할게요
  (2) 스킵할게요 — 다음으로
  (3) 무료 옵션이 있는지 먼저 알려주세요
```

### (3) 선택 시 — 무료 옵션 안내 표준

```
무료로 시작할 수 있는 길이 몇 가지 있어요. (정책은 자주 바뀌니 직접 확인 필요)

  - **Anthropic Claude**: 신규 가입 시 일정 크레딧 제공 (변동 가능)
  - **Google AI Studio (Gemini)**: 일정 RPM·일일 한도 무료 (변동 가능)
  - **OpenRouter**: 일부 무료 티어 모델 (변동 가능)
  - **로컬 LLM (13강 참고)**: Ollama 등으로 비용 없이 실행 가능

위 정보는 변경될 수 있어요. 가입 페이지에서 *현재 정책*을 꼭 확인해주세요.

어떻게 하시겠어요?
  (1) 무료 옵션으로 진행할게요 (어떤 거?)
  (2) 그냥 유료라도 진행
  (3) 일단 스킵
```

### 강의 자체 스킵 분기 (06-free-api-playbook 등)

비용 부담이 큰 강의는 *강의 자체*도 스킵 가능하게 합니다:

```
이 강의는 비용 발생 가능성이 큰 실습이 포함돼요.
부담되시면 강의 자체를 스킵하셔도 돼요. 13강에서 무료 로컬 LLM 옵션을 다뤄요.

  (1) 그래도 진행
  (2) 강의 스킵 → 다음 강의로
```

## 4. 명령어 안내 (학습자 OS 맞춤)

### 한 청크에 한두 개의 명령어만
청크당 명령어 1~2개. 모든 명령어에 *한국어 주석*.

### 표준 형식
```markdown
이 명령어를 터미널에 붙여넣어 주세요.
(이건 ~ 하는 명령이에요)

```bash
# 폴더 만들기
mkdir my-mcp-test

# 그 폴더로 이동
cd my-mcp-test
```

실행하셨으면 "됐어요" 또는 결과 화면을 알려주세요.
```

### "이렇게 질문해보세요" 패턴 (에이전트 사용법 학습)

명령어 실행이 아니라 *에이전트와 대화*가 필요한 실습은:

```markdown
이제 에이전트한테 직접 시켜볼게요. 다음 문장을 그대로 입력해보세요.

> 👉 "내 Documents 폴더에서 가장 최근에 수정한 파일 알려줘"

답이 나오면 화면을 보여주세요. (스크린샷이나 텍스트 복붙 둘 다 OK)
```

→ 비개발자에게 매우 중요. *명령어 실행*만이 아니라 *에이전트에게 자연어로 시키는 패턴*까지 학습.

---

## 5. 결과 받기

학습자가 명령어 결과·에이전트 답변을 붙여넣으면 에이전트가 분석합니다.

### 분석 분기
- ✅ 성공 → 6-A로
- ❌ 에러 → 6-B로
- 🤷 애매 → 추가 정보 요청 (예: "전체 출력을 그대로 보여주세요")

---

## 6-A. 성공 시 (success path)

```
잘 됐어요! 매튜님이 방금 한 일은 ~ 거예요.

이제 한번 더 응용해볼게요. 이렇게 질문해보세요:
  👉 "..."

다음 단계로 가시겠어요?
  (1) 네, 다음으로
  (2) 한 번 더 다른 걸 시도
  (3) 마무리
```

---

## 6-B. 에러 시 (debugging loop)

### 표준 흐름
1. 에러 메시지 받음
2. 에이전트가 분석:
   - **자주 있는 에러** → `practice/troubleshooting.md`(또는 `options/<id>.md` 안의 트러블슈팅 섹션) 참조해서 해결
   - **그 외** → 에이전트가 즉석 분석/검색 시도
3. 해결책 제시 (1~2개 명령어)
4. 학습자 재시도
5. 다시 결과 받기 → 5단계 분석으로 돌아감

### 디버깅 루프 한계 — 학습자가 포기할 때
3회 이상 재시도해도 풀리지 않거나, 학습자가 "포기할게요" 입력 시:

```
음, 이건 제 능력 밖이거나 환경 문제일 수 있어요.

  (1) 다른 옵션으로 다시 시도 (1단계로 돌아가기)
  (2) 일단 ⚠ 미이행으로 표시하고 다음 강의로
  (3) 매튜님이 이 에러 메시지를 강의 작성자에게 공유 (개선 자료)

어떻게 하시겠어요?
```

## 7. 마무리 + 일반화 + 진도 갱신

### 표준 마무리
```
✅ 실습 통과 축하드려요!

방금 배운 패턴은 다른 ~에도 똑같이 적용돼요.
예를 들어 [다른 옵션 1, 다른 옵션 2] 도 이런 식으로 하시면 돼요.

이번 실습 결과:
  - status: completed
  - practice_status: done
  - 진도가 자동으로 갱신됐어요.

다음 강의로 가실까요? 메뉴를 보시려면 "메뉴"라고 입력해주세요.
```

### 진도 갱신
- 통과 시: `progress[skill_id].practice_status = "done"`
- 학습자가 끝까지 시도했지만 풀지 못함 → 학습자가 (2) 선택 시: `practice_status = "not_done"`
- `last_visited_at` = 오늘 날짜
- `updated_at` = 오늘 날짜

---

## 8. 통과 판정 표

| 상황 | practice_status | 메뉴 표시 |
|---|---|---|
| 한 번에 성공 | done | ✅ |
| 여러 번 재시도 후 성공 | done | ✅ |
| 학습자가 포기 → "넘어가" / "스킵" | not_done | ⚠ |
| 진행하지 않음 (이론만 끝) | not_started 또는 not_done | ⚠ (이론은 ✅) |
| 디버깅 한계 → 학습자가 (2) 선택 | not_done | ⚠ |

→ **재시도 횟수와 무관하게**, 결국 성공하면 ✅. 포기하면 ⚠.

---

## 9. 에이전트 행동 체크리스트

가이드 실습 모드에서 매 응답마다 확인:

- [ ] 옵션 제시 시 번호 + 한 줄 설명 형식 지킴
- [ ] 비용 가능성 있는 실습엔 💰 안내 *반드시* 표시
- [ ] 명령어는 학습자 OS에 맞게만 출력 (양쪽 OS 동시 X)
- [ ] 모든 명령어에 한국어 주석
- [ ] 학습자에게 *결과를 보여달라*고 요청
- [ ] 학습자가 시도 전에 *답을 미리 보여주지 않음*
- [ ] 에러 시 즉시 다음 명령으로 점프하지 않고 *분석 → 해결책 → 학습자 재시도* 흐름
- [ ] 통과/포기 시 진도 갱신
- [ ] "넘어가" / "스킵" / "포기" 입력은 언제든 받아 처리

## 10. 옵션 파일 표준 구조 (`practice/options/<id>.md`)

옵션이 3개 이상이라 옵션 폴더를 사용할 때, 각 옵션 파일은 다음 구조를 따릅니다:

```markdown
# Option: <옵션 이름>

## 한 줄 요약
이 옵션은 ~ 합니다.

## 사전 점검
- 필요한 도구: ...
- 필요한 권한: ...
- 💰 비용: 무료 / 유료 / 일정 한도까지 무료
  - (유료라면 비용 안내문 표준 참조)

## 명령어 단계
1. ... (학습자 OS 자리표시자 사용)
2. ...
3. ...

## "이렇게 질문해보세요" 예시
> 👉 "..."

## 자주 발생하는 에러 + 해결
- 에러 메시지: `...`
  - 원인: ...
  - 해결: ...

## 마무리 안내
방금 배운 패턴은 ~에도 적용 가능합니다.
```

→ 새 옵션 추가 시 이 구조 그대로 채우면 됩니다.
