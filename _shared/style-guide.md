# Style Guide — 강의 표현·형식 가이드

이 문서는 모든 lesson 텍스트와 SKILL.md 본문 작성에 적용되는 *문체·형식 규칙*을 정의합니다.

---

## 1. 톤 — 친근한 존댓말

기본 어미: "~해볼게요", "~해보세요", "~하시면 돼요"

### ✅ 권장
- "이번에는 AGENTS.md를 만들어볼게요."
- "여기까지 이해되셨어요?"
- "한번 직접 입력해볼까요?"
- "이건 조금 어려울 수 있어요. 천천히 보시면 돼요."

### ❌ 피할 표현
- "~하라.", "~하시오." — 너무 명령조
- "야, 이거 해봐." — 너무 캐주얼
- "Step 1: Execute the following command." — 영어 직역체

### 칭찬·격려
- 학습자가 미션 통과: "잘 따라오셨어요! 다음으로 갈게요."
- 부분 합격: "거의 다 됐어요. 이 부분만 한 번 더 봐주세요."
- 어려워할 때: "여기서 헷갈리는 분들 많아요. 이렇게 생각해보면 어떨까요?"

---

## 2. 도구 비종속 표기

학습자는 Claude Code / Codex CLI / Cursor / Gemini CLI / Antigravity 중 무엇이든 사용할 수 있습니다.

### 본문에서는 "에이전트"로 통칭
- ✅ "에이전트가 이 명령을 실행하면…"
- ❌ "Claude가 이 명령을 실행하면…"
- ❌ "Codex가 이 명령을 실행하면…"

### 도구별 명령어 차이가 발생할 때

도구별 명령이 *반드시 달라야* 본문이 성립한다면, **부록 박스**로 처리합니다:

```markdown
> 💡 **도구별 명령 (부록)**
> - Claude Code: `/skill <name>`
> - Codex CLI: `codex run <name>`
> - Cursor: `@<name>` 또는 `/add-skill`
> - Gemini CLI: `gemini skills run <name>`
> - Antigravity: 자동 활성화 (description 트리거)
```

본문은 항상 추상적·도구 무관한 흐름으로 쓰고, 박스에서만 구체화.

## 3. OS 분기 — 학습자 프로필 참조

**한 번의 lesson 출력에서 두 OS 명령어를 동시에 보여주지 마세요.** 학습자 프로필 `os` 값을 보고 *해당 OS 명령만* 출력합니다.

### 예시

학습자 OS가 `darwin`(Mac)인 경우:
```bash
# 폴더 생성
mkdir -p my-agent
cd my-agent
```

학습자 OS가 `win32`인 경우:
```powershell
# 폴더 생성
New-Item -ItemType Directory -Path my-agent
Set-Location my-agent
```

### 작성 시
lesson 파일에는 *둘 다* 적되, 자리표시자로 분기합니다:

```markdown
{{os:darwin}}
```bash
mkdir -p my-agent
```
{{/os}}

{{os:win32}}
```powershell
New-Item -ItemType Directory -Path my-agent
```
{{/os}}
```

에이전트는 출력 시 학습자 OS에 맞는 블록만 골라 보여줍니다.

## 4. 도메인 동적 예시 — 하이브리드

본문은 *검증된 일반 설명*으로 작성하되, **도메인 맞춤 예시**가 들어갈 자리에 자리표시자를 둡니다.

### 자리표시자 형식
```
{{example:concept-name}}
```

### 사용 예
lesson 파일:
```markdown
MCP 서버는 에이전트와 외부 시스템을 잇는 다리입니다.
{{example:mcp-use-case}}
```

에이전트는 출력 시 학습자 프로필 `domain`을 참조해 1~2 문장으로 도메인에 맞춘 예시를 생성:
- domain="1인 콘텐츠 크리에이터" → "예를 들어 매튜님이 운영하시는 블로그의 글감을 외부 RSS에서 자동으로 가져오게 만들 수 있어요."
- domain="회의록 자동화" → "예를 들어 캘린더 MCP를 붙이면 오늘 잡힌 회의 안건을 자동으로 끌어올 수 있어요."

### 자리표시자 사용 원칙
- 사실관계가 중요한 핵심 개념은 본문에 직접 작성 (LLM 즉석 생성 X)
- 도메인 맞춤이 효과적인 *적용 예시*에서만 자리표시자 사용
- 한 청크당 자리표시자는 최대 1개

---

## 5. 명령어·코드·파일명

### 한국어 본문 + 영문 코드/명령어
- 본문: 한국어 (친근한 존댓말)
- 명령어·파일명·코드: 영문 그대로
- 코드 블록 안에 한글 주석 OK

### 모든 명령어에 주석 (비개발자 친화)
```bash
# 새 폴더 만들기
mkdir my-agent

# 그 폴더로 이동
cd my-agent
```

주석 없는 단독 명령은 피합니다.

---

## 6. 청크 길이

- 설명: **3~6 문장** (한국어 기준)
- 코드 블록: **0~1개** (한 화면을 넘기지 않게)
- 너무 짧으면(2문장) 합치고, 너무 길면(7문장 이상) 쪼갭니다.

---

## 7. 약어·기술 용어 + 0강 glossary 활용

처음 등장 시 *한국어 풀이 + 영문 약어*:
- "에이전트(Agent)는 사용자의 지시를 받아 자동으로 작업하는 프로그램이에요."
- "MCP(Model Context Protocol)는 에이전트와 외부 도구를 잇는 표준 규약이에요."

이후에는 약어만 사용해도 OK.

### 비개발자 친화 — 자주 막히는 용어 처리

다음 단어들은 *처음 등장 시 풀이*가 필요합니다 (lesson 파일에 박혀 있지 않더라도 에이전트가 *출력 시점*에 자동으로 풀어줘야 함):

| 카테고리 | 단어 |
|---|---|
| 컴퓨터·터미널 | CLI, 디렉토리, 권한, 관리자 권한, PATH |
| Git/GitHub | 커밋, 푸시, PR, 별, 저장소, 리포지토리, 이슈 |
| API/인증 | API, 키, 토큰, JSON, 엔드포인트, 401/403/429 |
| 도구 | Docker, 컨테이너, 이미지, 포트, npm, pip, 패키지 |
| LLM | 토큰, 컨텍스트 윈도우, 프롬프트 |

### 처리 방식 (3단계)

**1단계 — 첫 등장 시 본문 안에 짧은 풀이 한 줄**
```
"Git(파일 변경을 시간 순으로 기록하는 도구)으로 커밋하면..."
```

**2단계 — 처음 만난 단어에 박스 첨부 (선택)**
```
> 💡 *Docker가 처음이세요?* `00-prerequisites/resources/glossary.md`에서
> "박스에 담아 띄우는 도구"라고 짧게 정리해뒀어요.
```

**3단계 — 각 강의 *첫 청크*에 표준 안내 박스 (자동)**
```
> 💡 모르는 단어가 나오면 `00-prerequisites/resources/glossary.md`를 펼쳐보세요.
> 또는 0강(prerequisites)을 먼저 들으시면 강의가 더 매끄러워요.
```

### 에이전트의 책임 (중요)

lesson 파일에 *모든 용어 풀이가 박혀 있지 않더라도*, 에이전트는 출력 시점에 *학습자가 모를 만한 단어*를 발견하면 *glossary 안내 박스*를 자동으로 첨부해야 합니다. 학습자가 단어 하나에 막혀도 강의 흐름이 깨져요.

비개발자 학습자(`level: "non-developer"`)일 때 이 책임이 *훨씬 강해집니다*. 의심되면 *풀어 설명*하세요. 너무 많이 풀어주는 게 적게 풀어주는 것보다 안전합니다.

## 8. 이모지 — 절제해서 사용

기능적으로 의미를 갖는 이모지만 사용:
- 📘 lesson 헤더
- ❓ 이해 확인 질문
- 🛠 실습 미션
- 🔀 선택 분기
- ✅ 완료 / 합격
- ⏭ 스킵 / ⚠ 미이행 / 🔒 잠김
- 💡 부록·팁 박스

장식용 이모지는 쓰지 않습니다.
