# Practice — 가이드 실습 (14강 멀티에이전트)

> `_shared/guided-practice-protocol.md`의 7단계 + 🎯 **캡스톤 진입 분기 안내**.

## 0. 진입 직전 (draft 정리)

이론에서 적은 `agents_roles` / `communication_protocol` / `failure_handling`을 정리해 보여줌.

## 1. 옵션 제시 (2개 인라인)

```
어떤 워크플로우로 시연하시겠어요?

  (1) {{name}}님 본인 작업의 멀티에이전트 설계
  (2) 가상 시나리오 — 예: "리서치 → 작성 → 검토" 3에이전트

번호로 답해주세요.
```

## 2. 옵션 ① — 본인 작업

### 2-1. 패턴 결정
이론에서 고른 패턴(라우터/계층/병렬) 재확인. 다이어그램으로 시각화:

```
[입력] → [라우터] → A or B or C   (라우터)
[메인] → [전문가1, 전문가2] → 통합  (계층)
[입력] ⤵ A, B, C → 통합            (병렬)
```

### 2-2. 도구 선택
- 도구가 멀티에이전트 직접 지원 → 그 기능 사용
- 미지원 → **n8n 워크플로우** (10강 활용)
- 또는 *순차 실행* 폴백

### 2-3. 시연

각 에이전트의 *역할 + 입출력*을 정의한 채로 한 번 실행. 결과를 학습자가 붙여넣음.

### 2-4. 실패 시뮬레이션 (선택)
의도적으로 *한 에이전트가 빈 입력*을 받게 만들어 *실패 처리* 흐름 점검.

## 3. 옵션 ② — 가상 시나리오

강의 제공: "리서치 에이전트 → 작성 에이전트 → 검토 에이전트" 3단계. 각 에이전트의 역할·입출력을 함께 정의 → 시뮬레이션 호출.

## 4. 검증 기준

| 항목 | 통과 기준 |
|---|---|
| 역할 *2개 이상*이 *서로 다른 책임* | ✅ |
| 의사소통 형식이 *명시적* (JSON, 마크다운 등) | ✅ |
| 실패 처리 *1가지 케이스* 다룸 | ✅ |

3개 중 *2개 이상* 통과 시 ✅.

## 5. 트러블슈팅

- 메인이 통합을 잘못함 → 각 에이전트의 *출력 형식*을 더 명시
- 한 에이전트가 *과한 책임* → 더 작게 쪼개기
- 도구가 미지원 → n8n 또는 순차 실행 폴백
