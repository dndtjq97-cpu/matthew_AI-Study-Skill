# Lesson 14 — 멀티에이전트 설계 (심화 트랙 마지막)

> 학습자가 끝나면 2~3개 에이전트가 협력하는 워크플로우를 설계하고 시연한다.

심화 트랙의 마지막 강의입니다. 종료 시 *캡스톤(15강) 진입* 안내가 추가됩니다.

## 3. 이론 lesson 흐름
청크 8개.

### 14강에서 *왜* 한 청크씩 가는가
멀티에이전트 설계는 *시스템 사고*가 필요합니다. 한 번에 "라우터 패턴 쓰세요"라고 답을 주면 *왜*가 빠져요. 한 청크씩 *문제 → 패턴 → 적용 → 다음*으로 가야 본인 워크플로우에 맞는 패턴을 *선택*할 수 있습니다.

## 4. 가이드 실습 — 옵션 2개 인라인

### 4-0. 진입 시 draft 정리

```
🎉 이론 끝! 이제 멀티에이전트 워크플로우를 시연해볼 시간이에요.

📝 에이전트 역할들:
   - <draft.agents_roles[0]>
   - <draft.agents_roles[1]>
📝 의사소통 프로토콜: <draft.communication_protocol>
📝 실패 처리: <draft.failure_handling>
```

### 4-1. 옵션 제시

```
어떤 워크플로우로 시연하시겠어요?

  (1) {{name}}님 본인 작업의 멀티에이전트 설계
  (2) 가상 시나리오 — 예: "리서치 → 작성 → 검토" 3에이전트

번호로 답해주세요.
```

### 4-2. 가이드 흐름
도구별 멀티에이전트 호출 방식 안내 + 시연 → 실패 시뮬레이션 (의도적으로 한 에이전트가 실패) → 처리 확인.

### 4-3. 검증 기준

| 항목 | 통과 기준 |
|---|---|
| 역할 *2개 이상*이 *서로 다른 책임* | ✅ |
| 의사소통 형식이 *명시적* (JSON, 텍스트 등) | ✅ |
| 실패 처리가 *적어도 1가지* 케이스 다룸 | ✅ |

3개 중 2개 이상 ✅.
