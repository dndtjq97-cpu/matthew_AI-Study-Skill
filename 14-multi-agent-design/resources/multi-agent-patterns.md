# 멀티에이전트 패턴 모음

## 3가지 기본 패턴

### 1. 라우터 (Router)

```
[사용자 입력]
     ↓
  [라우터]
   ↓  ↓  ↓
   A  B  C
```

**언제 쓰나**: 입력이 *다양한 종류*고 종류별로 *처리 방법이 다름*.

**예시**: "메일 분류 → 회의 / 영업 / 단순 질문 → 각 전문가에게"

**구현 팁**:
- 라우터는 *분류만*. 처리는 X
- 분류 기준이 *명확*해야 안 흔들림

---

### 2. 계층 (Hierarchy)

```
   [메인]
    ↓
[전문가1] [전문가2] [전문가3]
    ↓        ↓         ↓
   [메인이 통합]
```

**언제 쓰나**: 큰 작업을 *부분 작업*으로 나눠 *전문 분담*.

**예시**: "회의록 → 요약(서브1) + 액션 추출(서브2) → 메인이 통합"

**구현 팁**:
- 각 전문가의 *책임 경계*를 명확히
- 메인은 *통합·검증*에만 집중

---

### 3. 병렬 (Parallel)

```
[입력]
   ↓
[A]  [B]  [C]   ← 동시 실행
   ↓   ↓   ↓
   [통합]
```

**언제 쓰나**: 같은 입력을 *다른 관점*에서 봐야 할 때.

**예시**: "글 1편을 → 문법 검토 + 사실 확인 + 톤 분석 → 종합"

**구현 팁**:
- 각 에이전트가 *독립적*으로 동작
- 결과 *통합 규칙*을 미리 정의 (다수결 / 메인 판단 등)

## 의사소통 프로토콜

### 가장 단순한 방식 — JSON + 메인 중계
```
[A] → {"result": "...", "confidence": 0.8} → [메인] → ...
```

### 마크다운 메시지
```
[A] → "# 결과\n- 항목 1\n- 항목 2" → [메인] → ...
```

### 실패 메시지 형식 (필수)
```json
{
  "status": "failed",
  "reason": "...",
  "suggestion": "..."
}
```

## 실패 처리 4가지 패턴

| 패턴 | 동작 |
|---|---|
| **재시도** | 실패 시 한 번 더. 간단. |
| **폴백** | 실패 시 다른 에이전트가 대신. |
| **합의** | 여러 에이전트 답 → 다수결 또는 메인 판단. |
| **롤백** | 실패 시 이전 상태로 복귀. |

처음에는 *재시도 + 메인 검증* 조합으로 시작.

## 디버깅 패턴

| 증상 | 점검 |
|---|---|
| 결과가 어색 | 어느 에이전트가 잘못? 단계별 로그 |
| 형식이 깨짐 | 입출력 *형식 명시* 강화 |
| 한 에이전트가 *멈춤* | 타임아웃 + 재시도 |
| 통합이 어긋남 | 메인의 *통합 로직* 점검 |
