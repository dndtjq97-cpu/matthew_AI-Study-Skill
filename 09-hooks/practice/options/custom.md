# Option: 학습자 선택 트리거

## 한 줄 요약
저장·커밋 외 *다른 트리거*를 학습자가 직접 선택해서 만듭니다.

## 흔한 학습자 선택지
- **시간 기반** — 매일 오전 9시
- **외부 이벤트** — 메일 도착 시, 메시지 수신 시
- **도구 이벤트** — 빌드 완료 시, 배포 후

## 진입 시 학습자에게 묻기

```
어떤 트리거를 만들고 싶으세요? 한 줄로 적어주세요.
예시:
- "매일 오전 9시 메일 요약"
- "GitHub 이슈 새로 열릴 때 슬랙 알림"
```

## 사전 점검 (선택한 트리거에 따라)
- 시간 기반 → 시스템 cron 또는 도구 스케줄러
- 외부 이벤트 → 그 이벤트를 *감지할 도구*가 있는가?
- 도구 이벤트 → 도구의 webhook·hook 지원 여부

## hook 정의 (개념)

```
on: <트리거>
when: <조건>
action:
  - <액션 단계 1>
  - <액션 단계 2>
safe:
  - <엣지 케이스 처리>
```

## 등록 + 발사 테스트

선택한 트리거에 맞는 등록 방법은 함께 안내. 등록 후 *수동으로 트리거 발생*시켜 hook이 발사되는지 확인.

## 안전 점검 공통

- [ ] 무한 루프 가능성?
- [ ] 외부 시스템에 *과한 호출* 가능성?
- [ ] 실패 시 *원래 상태 보존*?

## 자주 발생하는 에러
- 트리거가 *예상과 다른 시점*에 발사 → 트리거 조건 다시 확인
- 외부 의존 실패 (네트워크 등) → 재시도 로직 추가

## 마무리 안내

직접 만드신 hook은 *본인 작업 흐름*에 가장 잘 맞을 거예요. 다음에 다른 hook을 만들 때도 같은 7단계로.
