# Hook 안전 가이드

## 가장 큰 위험: 무한 루프

hook이 *자기 자신을 다시 트리거*하면 끝없이 도는 상태가 됩니다.

### 무한 루프 예시
- 파일 저장 시 자동 포맷팅 → 포맷팅 후 *파일이 다시 저장됨* → 또 트리거 → 반복
- 메일 도착 시 답신 → 답신이 다시 메일 → 또 트리거

### 방지 패턴

**1. 변경 감지**
```
액션 실행 후 결과가 *원본과 같으면* 저장 안 함.
```

**2. 재진입 방지 플래그**
```
hook이 발사 중일 때 *중복 발사* 막음. 끝나면 플래그 해제.
```

**3. 깊이 제한**
```
한 번의 hook 실행 안에서 *N번 이상* 트리거되면 강제 종료.
```

## 안전 체크리스트

새 hook 만들 때마다 점검:
- [ ] 액션이 *5초 이내* 끝나는가?
- [ ] 무한 루프 가능성을 *명시적으로* 차단했는가?
- [ ] 실패 시 *원래 상태*로 복구되는가?
- [ ] 외부 시스템(메일, 메신저 등) 호출 시 *재시도 한도*가 있는가?
- [ ] hook 비활성화 방법을 *알고 있는가*?

## 비활성화 빠른 방법

도구별 위치:
- pre-commit: `pre-commit uninstall` 또는 `git commit --no-verify`
- 편집기 hook: 도구 설정에서 hook 항목 주석 처리
- cron: `crontab -e` 편집

비활성화는 *응급* 시에만. 평소엔 hook 자체를 다듬는 게 좋아요.

## 안전한 hook 출하

- hook을 *처음 만들면* 1주일 동안 자세히 관찰
- 의도치 않은 결과가 한 번이라도 발생하면 *즉시 비활성화* 후 수정
- 익숙해진 후에 다음 hook 추가
